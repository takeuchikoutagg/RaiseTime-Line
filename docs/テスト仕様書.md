## 5. 自動テスト（E2E）との対応

このシナリオの主な手順は、Playwright の E2E テスト（`frontend/e2e/`）で自動化している。Chromium・WebKit（Safari と同じ描画の仕組み）・Microsoft Edge の3つで動かす。

- 実行：`docker compose up -d` のあと `cd frontend && npm run e2e`（バックエンド・フロントエンドが動いていなければ start.sh で起動する）。結果のレポートは `npm run e2e:report`
- 初めて動かすときは、テスト用のブラウザを入れる：`npx playwright install chromium webkit`（Edge はインストール済みのものを使う）
- テストごとに `e2e_` で始まる新しいユーザーを作る（開発用のデータには頼らない）。作ったユーザーは DB に残る

## 6. Safari・Edge で手で確かめる方法

Safari・Edge での確認は、5章の E2E で自動化している。本物の Safari（特に iPhone）で手で確かめる場合は、Chrome と同じ手順を行い、各表の「Safari」「Edge」の欄に OK / NG を書く。

1. 「2. 準備」のとおりにサーバーを起動する
2. Safari はプライベートウィンドウ、Edge は InPrivate ウィンドウで `http://localhost:5174/` を開く
3. テスト用のアカウントは、すでにあれば別の名前（`qa_alice3` など）で作る。QAボブの投稿（SC-08-2）は、別のウィンドウで QAボブとしてログインして投稿してもよい
4. スマホ幅（SC-10）は、Safari は「開発 → レスポンシブ・デザイン・モード」、Edge は開発者ツールのデバイスツールバーで確かめる。実機の iPhone で開ける場合は、それがいちばん確実
5. 特に、ブラウザによって違いが出やすい次の点をよく見る
   - 画像の選択と縮小（SC-02-3〜5、SC-07-4）
   - Cookie によるログインの維持（SC-01-8、SC-07-6）
   - 「新しい投稿があります」（SC-08）。タブを裏にしている間は確かめないので、表に出したまま待つ
