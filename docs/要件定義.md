# 要件定義書 - RaiseTime Line

X（旧Twitter）を参考にした、タイムライン型のテキストSNS。学習目的で開発する。

## 1. 概要

受講生や個人が、学習の記録や日々の気づきを気軽に投稿できる、タイムライン型のテキストSNSを作る。
少人数での利用を想定しているが、**複数ユーザーが使う前提**で設計する（他のユーザーの投稿にいいね・コメントをする、いいね数・コメント数が誰からでも見える）。

学習の目的は、認証、CRUD、1対多・多対多（自己参照を含む）のリレーション、画像アップロード、AWS でのインフラ構築といった Web アプリの基本を一通り身につけること。

## 2. 対象ユーザー

| ユーザー | 説明 |
|---|---|
| 受講生 | 同じ講座の受講生どうしで、学習の記録や気づきを投稿・共有する |
| 個人 | 日記やメモのように個人で使う。気が向けば他のユーザーをフォローする |

- 誰でも新規登録でき、自分でアカウントを作れる
- アクター（登場人物）は「未ログインユーザー」と「ログインユーザー」の2種類

## 3. 利用環境

| 項目 | 内容 |
|---|---|
| 利用デバイス | PC・スマートフォン（ブラウザ） |
| スマートフォン対応 | 必要（レスポンシブ表示） |
| ログイン機能 | 必要（メールアドレス＋パスワード） |
| データ保存先 | PostgreSQL（投稿・ユーザーなどのデータ）、AWS S3（画像ファイル） |

## 4. コンセプトと差別化

**「数字に振り回されず、つながっている人の投稿だけを落ち着いて読めるSNS」**

X/Twitter に近い使い心地にしつつ、次の機能を**あえて作らない**ことで差別化する。

| 作らない機能 | 理由 |
|---|---|
| インプレッション数（表示回数）の表示 | 「どれだけ見られたか」を気にせず投稿できるようにするため |
| リツイート（リポスト）・引用 | 拡散の仕組みを持たず、フォローしている人の投稿だけで完結させるため |
| トレンド・おすすめ表示 | アルゴリズムではなく、時系列とフォロー関係だけでタイムラインを作るため |

- いいね数とコメント数は表示する。受け取った反応が分かるようにするため

## 5. 機能要件

全11機能。一覧は [docs/機能一覧.md](./機能一覧.md)、機能ごとの詳しい仕様は [docs/機能定義書/](./機能定義書/) を参照。

| ID | 機能 | 概要 |
|---|---|---|
| F-01 | 新規登録 | 名前・@ユーザーID・メールアドレス・パスワードでアカウントを作る |
| F-02 | ログイン・ログアウト | メールアドレスとパスワードで認証する |
| F-03 | タイムライン | 自分とフォロー中ユーザーの投稿を新しい順に表示する |
| F-04 | 投稿作成 | テキスト（280文字まで）を投稿する。画像を添付してもよい |
| F-05 | コメント | 投稿にコメントする（自分の投稿にも他人の投稿にもできる） |
| F-06 | いいね | 投稿にいいね／いいね解除をする。いいね数を表示する |
| F-07 | フォロー | 他のユーザーをフォロー／フォロー解除する |
| F-08 | ユーザーページ | 特定ユーザーの投稿一覧とフォロー状況を表示する |
| F-09 | ユーザー検索 | @ユーザーIDまたは名前で、フォローしたいユーザーを探す |
| F-10 | 投稿編集 | 自分の投稿の本文・画像を変更する。「編集済み」と表示する |
| F-11 | 投稿削除 | 自分の投稿を、確認のうえ削除する |

## 10. 技術スタック

| 区分 | 技術 | 用途 |
|---|---|---|
| フロントエンド | React + Vite（JavaScript） | 画面（SPA）。バックエンドの REST API を呼び出す |
| バックエンド | Spring Boot 4.1.0 / Java 25（Gradle） | REST API、認証（Spring Security） |
| DB アクセス | MyBatis | SQL を Mapper XML に書く（JPA は使わない） |
| マイグレーション | Flyway | テーブルの作成・変更を SQL ファイルで管理する |
| 認証 | Spring Security（OAuth2 Resource Server） | JWT のアクセストークン（15分）とリフレッシュトークン（7日）。どちらも HttpOnly Cookie で渡す |
| データベース | PostgreSQL 17 | ユーザー・投稿・コメント・いいね・フォローの保存。開発中は Docker Compose で動かす |
| 画像の保存先 | AWS S3 | 投稿画像のファイルを保存する。DB には S3 のキーだけを持つ |
| インフラ（案） | AWS（CloudFront / ALB / EC2 / RDS / S3） | [インフラ構成図](./インフラ構成図.md) を参照 |
| ドキュメント | Markdown | 設計ドキュメント（図は Mermaid） |

## 11. 非機能要件

| 分類 | 内容 |
|---|---|
| デザイン | X に近いシンプルな1カラムのタイムライン。**インプレッション数・リツイートボタンは置かない** |
| 対応ブラウザ | 最新の Chrome / Safari / Edge（PC・スマートフォン） |
| レスポンシブ | PC とスマートフォンの両方で使えること |
| 性能 | タイムラインは1ページ20件ずつ表示する（「もっと見る」または無限スクロール）。1回の表示で数百ミリ秒程度を目安にする |
| 入力制限 | 投稿本文・コメント本文：1〜280文字。名前：1〜50文字。@ユーザーID：3〜15文字（半角英小文字・数字・`_`）。パスワード：8〜64文字かつ UTF-8 で72バイト以内 |
| 入力制限 | 文字数はフロントエンドとバックエンドの両方で検証し、数え方をそろえる（絵文字も1文字と数える。Java の `String.length()` では絵文字が2文字と数えられるため、`codePointCount` を使う） |
| 入力制限 | 画像：1投稿につき最大4枚、1枚5MBまで、形式は JPEG / PNG / GIF / WebP（※仮の値） |
| セキュリティ | パスワードは BCrypt でハッシュ化して保存する（平文では保存しない）。BCrypt が72バイトまでしか扱えないため、パスワードに上限を設ける |
| セキュリティ | ログインしていないユーザーは、ログイン画面と新規登録画面以外にアクセスできない |
| セキュリティ | 投稿の編集・削除は投稿者本人だけができる。画面でメニューを隠すだけでなく、API でも投稿者かどうかを必ず確認する（認可） |
| セキュリティ | 投稿・コメントの本文はエスケープして表示する（XSS 対策。React の通常の表示ではエスケープされるため、`dangerouslySetInnerHTML` は使わない） |
| セキュリティ | CSRF 対策をする（Spring Security の Cookie ＋ ヘッダー方式。CSRF トークンを `XSRF-TOKEN` Cookie で受け取り、`X-XSRF-TOKEN` ヘッダーで送り返す） |
| セキュリティ | AWS のアクセスキーはソースコードに書かない。EC2 から S3 へは IAM ロールで権限を与える |
| セキュリティ | JWT の署名に使う秘密鍵（32バイト以上）はソースコードに書かず、本番は環境変数 `JWT_SECRET` で渡す。本番ではトークンの Cookie に `Secure` を付ける（`AUTH_COOKIE_SECURE=true`） |
| セキュリティ | DB のパスワードなどの秘密情報は、環境変数や AWS Systems Manager Parameter Store で渡す |
| 可用性 | 学習用のため、停止しても大きな問題はない。ただし構成は ALB を使い、EC2 を増やせる形にしておく |
| 保守性 | フロントエンドとバックエンドを分け、REST API でやり取りする |

## 12. 制約条件

- 技術スタックは React / Spring Boot / PostgreSQL / AWS S3 とする
- 画像の保存先は AWS S3 とする
- ドキュメントは Markdown で書く
- 学習目的の個人開発のため、AWS の費用はできるだけ抑える

## 13. 今後の検討事項（本要件には含まないが、将来拡張の可能性があるもの）

- コメントの編集・削除（投稿の編集・削除は F-10・F-11 で作る）
- 投稿の編集履歴の表示
- プロフィール（アイコン・自己紹介・名前）の編集
- 新規登録時のメール認証、パスワードリセット
- Google や GitHub などのソーシャルログイン
- 通知、DM、投稿の検索、ハッシュタグ
- いいねしたユーザーの一覧、フォロー／フォロワーの一覧
- いいね数・コメント数のカウンターキャッシュ化（投稿が増えて集計が遅くなった場合）

> リツイート・引用、インプレッション数、トレンドはコンセプト上、将来も作らない。
