# テスト観点表 - RaiseTime Line

機能ごとに「何を確かめるべきか（観点）」を並べ、それを**どのテストで確かめているか**をまとめた表。テストの抜けを見つけ、次に何をテストするかを決めるために使う。

- 対象：F-01〜F-12 の全機能と、共通の仕組み（認証・CSRF・エラー）、非機能（性能・セキュリティ・アクセシビリティなど）
- 自動テストの数：バックエンド 275件、フロントエンド 211件、E2E 14件（Chromium・WebKit・Edge の3つで動かすので42回）（2026-10-05 時点）
- 機能を足したり変えたりしたら、この表も同じ Pull Request で更新する

## 1. 読み方

### 状態の記号

| 記号 | 意味 |
|---|---|
| ✅ | 自動テストで確かめている（`./gradlew test`・`npm test` で毎回動く） |
| 🖐 | 手で動かして確かめたが、手順と結果の記録が無い（→ シナリオテストで記録する） |
| △ | 一部だけ確かめている |
| ❌ | まだ確かめていない |
| 📋 | 手動のシナリオテストで確かめ、[テスト仕様書](./テスト仕様書.md) に記録がある |

### テストの場所

| 書き方 | 意味 | 場所 |
|---|---|---|
| BE: `XxxTest` | バックエンドのテストクラス | `backend/src/test/java/com/example/raisetime/` |
| FE: `Xxx.test.jsx` | フロントエンドのテストファイル | `frontend/src/` の、テストする部品の隣 |
| E2E: `xxx.spec.js` | 本物のブラウザ（Chromium・WebKit・Edge）で画面を通して操作する E2E テスト（Playwright） | `frontend/e2e/`。実行は `cd frontend && npm run e2e` |

バックエンドのテストは、種類で3つに分かれる。

| テストクラス | 種類 | 何を確かめるか |
|---|---|---|
| `*ServiceTest` | 単体テスト（DB などはモック） | 業務ルール：文字数・権限・冪等・画像の後始末など |
| `*MapperTest` | 結合テスト（本物の PostgreSQL） | SQL：並び順・カーソル・件数・制約（UNIQUE・CHECK・外部キー） |
| `*ControllerTest` | 結合テスト（Spring Security 込み） | API の入口：ステータスコード・401・403（CSRF）・JSON の形 |

### 観点の種類

| 観点 | 例 |
|---|---|
| 正常系 | 正しく使ったら成功する |
| 入力の誤り | 空・長すぎる・形式が違う → 400 |
| 境界値 | 上限ちょうどは OK、上限を1つ超えると NG（280文字／281文字など） |
| 認証 | ログインしていない → 401 |
| CSRF | `X-XSRF-TOKEN` ヘッダーが無い → 403 |
| 認可 | 他人のデータを操作しようとした → 403 |
| 存在しない | 対象が無い・途中で消された → 404 |
| 冪等・連打 | 同じ操作を2回しても結果が壊れない |
| 画面の動き | 表示・ボタンの状態・失敗したときのメッセージ |
